# NewsBroadcaster — Plugin Documentation

**Plugin:** NewsBroadcaster  
**Version:** 1.0.0  
**Author:** DEDA  
**Framework:** Oxide / uMod (Rust)

---

## Overview

NewsBroadcaster is a Rust server plugin that lets admins post rich in-game news announcements with a modern CUI (Client UI). Announcements have a title, an optional image, body text and a coloured type badge. Players get a notification toast when news is posted and can browse the archive at any time with `/news`.

Requires **Oxide (uMod)**. Other plugins are only needed for the features that use them: **ServerRewards** for RP rewards, **Economics** for currency rewards and **Notify** if `UseNotifyPlugin` is on. **ImageLibrary** is optional (it caches post pictures). Discord posts only need a webhook URL. See [Requirements](#requirements).

## What's in 1.0.0

1.0.0 is the first release of the new NewsBroadcaster. If you ran one of the earlier builds (numbered up to 1.2.0), your config, themes, language file and announcements carry over automatically; just replace the `.cs` file. The lists below say what is in it and what changed since those builds.

### A premium look
- **Rounded, smooth edges everywhere.** Panels, cards, buttons, pills, inputs and even pictures have soft anti-aliased corners. The corner images are generated by the plugin at startup; no extra plugin or download is needed. Set `RoundedCorners` to `false` for the classic square look.
- **Soft shadows and glass highlight.** Panels float on a blurred, dimmed background with a layered rounded shadow and a faint highlight along the top edge.
- **Clean, flat design.** Thin dividers replace the heavy header and footer bars. Only the main action on each screen is a filled button; everything else is soft and subtle. Your theme colours still drive everything.
- **Article-style popup.** Type pill and server name in the header, then the title, a "posted by · date" line, then the text. Long titles shrink to fit instead of being cut off.
- **Smooth animations.** Screens reveal top-to-bottom, archive rows cascade in, toasts fade in and out, likes pop and poll bars fade in. Switching screens no longer flashes the game behind the menu. It all runs on the player's client: no lag, no extra traffic.

### For players
- **Polls.** Any post can have a 2–4 option poll. Vote with one click, see live result bars, and change your vote.
- **Unread tracking.** `NEW` badges, an unread counter and a **Mark all read** button in the archive, plus one chat reminder about posts missed while offline.
- **Better archive.** Clickable rounded cards with thumbnails, type labels, like counts and poll vote counts.
- **Popup navigation.** Prev/next arrows with a `2 / 7` counter; "back to archive" returns to the same page.
- **Live countdown.** Popups that close by themselves show "CLOSES IN 12S"; liking or voting keeps them open.
- **Smoother likes and votes.** Only the button or poll redraws, so the scroll position is kept.
- **Archive filters and search.** Chips for All, Info, Warning, Alert, Event, Update and Polls, plus a search box that looks through titles and text.
- **Event countdowns.** A post can show a live timer such as "EVENT STARTS IN 2 DAYS 04:12:33"; the archive shows it too.
- **Timed polls.** Polls can close on their own; the popup shows "CLOSES IN 5H 12M" and everyone gets the result in chat.
- **News settings** (`/news settings` or the SETTINGS button): turn off the notification sound, the pop-ups (a short chat line instead) or the post shown when joining.
- **New chat commands:** `/news latest`, `/news read`, `/news settings`, `/news help` and `/news admin`.

### For admins
- **Better editor.** Content on the left, settings on the right: one-click type chips; **Pin to top**, **Notify online players**, **Post to Discord** and **Add poll** toggles; **Preview** before publishing. Fields no longer lose focus while you type.
- **Drafts.** **SAVE DRAFT** keeps a post unpublished (only admins see it). Publish it later from the editor, the **PUBLISH** button in News Management, or `news.publish`.
- **Copy post.** **COPY** opens the editor with a post's content and settings as a new post, handy for weekly wipe posts.
- **Posts for one group.** **WHO CAN SEE IT** limits a post to an Oxide group (VIP, staff...). Others don't see it anywhere; admins see it with a `VIP ONLY` badge.
- **Auto-delete.** Remove a post automatically 1, 3, 7, 14 or 30 days after publishing.
- **Poll timer and results.** Close a poll after 1 hour to 7 days; the result goes to chat and Discord when it closes (also when you close voting yourself).
- **Image link check.** The editor warns about links that won't show in game: imgur pages, Discord links (they expire), GIF / WEBP, web pages instead of pictures.
- **Character counters** next to the title and the text.
- **Notification position.** Six spots (top or bottom, left / centre / right) plus fine X / Y offsets.
- **RESEND** re-notifies everyone online about an existing post (button or `news.resend`).
- **News Management dashboard.** Five stat cards (published, drafts, reads, likes, poll votes), tabs with counts (All, Published, Drafts, Pinned, Polls), a search box and a sort order (newest, oldest, most read, most liked). Rows show the picture, type and status badges, when a post deletes itself or its poll closes, and reads / likes / votes as numbers.
- **Editor autosave.** Everything typed in the editor is kept. After a disconnect, a restart or a plugin reload, News Management shows the unsaved post with **CONTINUE EDITING** and **DISCARD**.
- **Post from other plugins.** `API_PostNews` / `API_CreateNews` let an event or wipe plugin publish through NewsBroadcaster (see API methods).
- **Theme picker** with colour swatches and pages for extra themes.
- **Console:** `news.poll`, `news.resend`, and `news.delete` / `news.list` with ids.
- **Discord:** type-coloured embeds with timestamp, avatar, poll options and optional `@here` / `@everyone`.

### Fixed since the earlier builds
- Clicking a button rebuilt the whole menu: it blinked and the mouse jumped back to the middle of the screen. Now only the content is swapped, in one step, and the cursor stays put.
- Long titles were cut off at the top of the popup.
- The 6th theme button spilled outside the theme panel.
- The notification sound played at the player's position for everyone nearby; it is now private.
- ServerRewards points failed to pay on current Rust builds (wrapped player id).
- `/n` broke normal words such as `w/new`.
- An admin's editor was replaced by a forced popup when news was posted.
- Players saw a post again as a popup after respawning even though they had already got it live.
- Pinned posts could be deleted by the `MaxStoredAnnouncements` limit.
- The title outline never rendered.
- UI layout broke on servers whose system language uses a comma as the decimal separator.
- An ImageLibrary placeholder showed while an image was still downloading.
- The data file was rewritten on every like or read; saves are now batched and flushed on server save and unload.
- **BACK** in the theme picker rebuilt the whole menu (a blink, and the mouse jumped to the middle).
- `news.show "Title" - Restart in 5` read the `5` as a post type and cut it from the text.
- `news.trigger` counted posts differently from `news.list` when drafts were stored, and said "triggered" even when the player could not see the post. It now takes the same index or id as the other commands and tells you when the player can't see it.
- **Mark all read** also marked group posts the player could not see yet.
- A poll whose timer had run out could still be clicked for up to 30 seconds (the vote was ignored).
- A toast for a post that had been deleted stayed on screen when clicked.
- A language file with a broken `{0}` placeholder could stop a command from working.
- Players who never came back stayed in the data file forever; old "last seen" markers are now cleaned up on load.

### Config options added since the earlier builds
`UnreadReminderOnConnect`, `RequireViewPermission`, `StripLinksFromBody`, `PopupImageFrame` (`Tall` / `Wide`), `ArchiveThumbnails`, `RoundedCorners`, `Notification.Position` (now six positions), `Notification.OffsetX` / `OffsetY`, `Discord.AvatarUrl`, `Discord.PostGroupOnlyPosts`, `Discord.PostPollResults`, `Polls.AllowVoteChange`, `Polls.ShowResultsBeforeVoting`, `Polls.AnnounceResults`. All are added to your config with their defaults on first load.

## Requirements

| Plugin | Needed | What for |
|---|---|---|
| Oxide (uMod) | **Always** | NewsBroadcaster is an Oxide plugin |
| ServerRewards | For RP rewards | Pays `Points` in the read / like rewards |
| Economics | For currency rewards | Pays `Currency` in the read / like rewards |
| Notify | Only with `UseNotifyPlugin: true` | Shows the new-post notification in Notify's style. If Notify isn't loaded, the plugin's own toast is shown |
| ImageLibrary | No | If installed, post pictures are cached through it so they load faster; otherwise the game loads the image link directly |

A reward that includes `Points` or `Currency` isn't paid while its plugin is missing, including any items in the same reward. The console prints a warning, and the reward isn't marked as paid, so it can still be paid after you install the plugin. Item rewards, polls, countdowns, rounded corners and Discord webhooks need nothing but Oxide.

## Console / RCON Commands

| Command | Permission | Description |
|---|---|---|
| `news.show "Title" "ImageURL" "Body" [Type]` | Admin | Post a new announcement (notifies players, posts to Discord) |
| `news.poll "Title" "Text" "Option 1\|Option 2\|..." [Type]` | Admin | Post an announcement with a poll (2–4 options separated by `\|`) |
| `news.list` | Admin | List stored announcements with index, id, reads and likes (plus `[DRAFT]`, `[GROUP vip]`, delete and poll times) |
| `news.publish <index\|id>` | Admin | Publish a draft (notifies players, posts to Discord) |
| `news.delete <index\|id>` | Admin | Delete an announcement |
| `news.resend <index\|id>` | Admin | Re-send the notification for an announcement to online players |
| `news.trigger <SteamID/Name> [index\|id]` | Admin | Force-show a popup to one player: the newest post they can see, or the one with that `news.list` index / id |
| `news.admin` | Admin | Open the in-game admin panel |

Index `0` is always the newest announcement.

### `news.show` usage

```
news.show "Server Update" "https://example.com/img.png" "The server has been updated!" Update
news.show "Alert!" "-" "PvP zone closing in 10 minutes." Alert
```

- Use `"-"` as the image URL to post without an image.
- Types: `Info`, `Warning`, `Alert`, `Event`, `Update` (case-insensitive, default `Info`). The type is only read when it is the last, unquoted word.
- Use `\n` for a new line.
- If the image link looks wrong (an imgur page, a Discord link, a GIF...), the console prints a warning after posting.

## The editor

`/news admin` → **NEW ANNOUNCEMENT** (or **EDIT** / **COPY** on a row). The content is on the left, the settings on the right.

| Control | What it does |
|---|---|
| Title / Image URL / Content body | Text fields. Enter (or `\n`) makes a new line in the body. An invalid image URL is rejected with a chat message |
| Counters | `23 / 120` next to the title (yellow when the title starts to shrink, red at the limit) and the body's character count (yellow when players will need to scroll) |
| Image link check | Under the image field: `✓ Direct image link`, or a warning for imgur pages, Discord links (they expire), GIF / WEBP, or links that don't end in `.png` / `.jpg` |
| Type chips | Pick one of the five types |
| **PIN TO TOP** | Pin the post (same as the PIN button in the list) |
| **NOTIFY ONLINE PLAYERS** | New posts and drafts: send the toast/popup to everyone who can see it (on by default). Edits: **RE-NOTIFY PLAYERS**, off by default |
| **POST TO DISCORD** | New posts and drafts, shown when the Discord webhook is configured |
| **ADD POLL** | Shows four poll option fields under the body. Fill 2–4 of them; empty ones are skipped. When editing a published poll, **CLOSE VOTING** stops new votes and announces the result. Turning **ADD POLL** off removes the poll and its votes |
| **WHO CAN SEE IT** | Click to step through `EVERYONE` and your Oxide groups (e.g. `VIP ONLY`) |
| **AUTO-DELETE** | `NEVER`, or delete 1 / 3 / 7 / 14 / 30 days after publishing. When editing a live post, a new choice counts from now |
| **COUNTDOWN TITLE / COUNTS DOWN TO** | A live timer in the popup, e.g. `WIPE IN` + `2d 4h`, `90m`, `19:00` (next time the server clock shows it) or `2026-11-12 19:00`. Times are server time; the line under the field shows when it ends |
| **POLL CLOSES** | `MANUALLY`, or close the poll 1 / 6 / 12 hours or 1 / 3 / 7 days after publishing |
| **PREVIEW** | Shows the popup exactly as players will see it. Nothing is published; **BACK TO EDITOR** returns with your draft intact |
| **SAVE DRAFT** | New posts and drafts: save without publishing |
| **PUBLISH / SAVE CHANGES** | A title is required |

Editing keeps likes, reads and reward history, and adds an `EDITED` marker. A published post can't be turned back into a draft.

### General

| Key | Default | Description |
|---|---|---|
| `AutoCloseSeconds` | `15` | Seconds before a broadcast / connect popup closes by itself (shown as a live countdown) |
| `EnableAutoClose` | `true` | Auto-close broadcast and connect popups (popups a player opens never auto-close) |
| `ShowNewsOnConnect` | `true` | Show the newest post to a player who has not seen it yet when they wake up |
| `UnreadReminderOnConnect` | `true` | Once per session, tell the player in chat how many posts they missed since their last visit |
| `RequireViewPermission` | `true` | `false` = everyone can see news without `newsbroadcaster.view` |
| `ServerName` | `"SERVER NEWS"` | Label in the UI headers and the Discord embed |
| `AnnouncementsPerPage` | `5` | Rows per archive / admin page (1–8) |
| `MaxStoredAnnouncements` | `50` | Max posts kept (1–500). Oldest unpinned posts are removed first; pinned posts are kept |
| `StripLinksFromBody` | `true` | Remove `http(s)://` and `www.` links from new post bodies (as the earlier builds did). Existing posts are never changed |
| `PopupImageFrame` | `"Tall"` | `"Tall"` fills the popup's left column (the classic look). `"Wide"` uses a 16:9 frame so widescreen images aren't stretched |
| `ArchiveThumbnails` | `true` | Show image thumbnails in the archive |
| `RoundedCorners` | `true` | Rounded, anti-aliased corners on all panels, cards, buttons and pictures. `false` = square corners |

| Key | Default | Description |
|---|---|---|
| `Enabled` | `true` | Show the toast for new posts. `false` = open the popup directly instead |
| `UseNotifyPlugin` | `false` | Send the notification through the Notify plugin |
| `NotifyType` | `0` | Notify plugin type index |
| `Position` | `"TopRight"` | Toast position: `TopRight`, `TopLeft`, `TopCenter`, `BottomRight`, `BottomLeft` or `BottomCenter`. The bottom ones sit above the hotbar and health bars. The old values `Right` / `Left` mean the top corners |
| `OffsetX` / `OffsetY` | `0` | Nudge the toast (1280×720 reference units: +X right, +Y up), e.g. to clear another plugin's HUD |

### Discord

| Key | Default | Description |
|---|---|---|
| `Enabled` | `false` | Post new announcements to Discord |
| `WebhookUrl` | `""` | Channel webhook URL |
| `BotName` | `"Server News"` | Webhook display name (empty = webhook default) |
| `AvatarUrl` | `""` | Optional webhook avatar image URL |

The embed has a type-coloured side bar, a `TYPE • SERVER NAME` header, the title, body (truncated at 4000 characters), image, "Posted by" footer and Discord's timestamp. Only the configured `RoleMention` can ping — text inside titles and bodies never does.

### Rewards

| Key | Default | Description |
|---|---|---|
| `EnableReadReward` | `false` | Pay the read bundle when a player keeps a post open for `ReadDelaySeconds` |
| `ReadDelaySeconds` | `5` | Seconds the popup must stay open to count as read |
| `ReadRewards` | scrap × 5 | Read bundle |
| `EnableLikeReward` | `false` | Pay the like bundle on a player's first like of a post |
| `LikeRewards` | scrap × 10 | Like bundle |
| `NotifyOnReward` | `true` | Tell the player in chat what they received |
| `PointsLabel` / `CurrencyLabel` | `"RP"` / `"coins"` | Labels used in that message |

Each bundle can combine **Items** (any shortname, optional `SkinId`), **Points** (ServerRewards) and **Currency** (Economics). Rewards are paid at most once per player per post. Full inventory → items drop at the player's feet. If a needed plugin is missing, the reward is skipped with a console warning and **not** recorded, so it can be paid later. Old configs with bare item arrays are migrated automatically.

### Polls

| Key | Default | Description |
|---|---|---|
| `AllowVoteChange` | `true` | Players can switch their vote by clicking another option |
| `ShowResultsBeforeVoting` | `false` | Show result bars to players who haven't voted yet (admins always see them) |
| `AnnounceResults` | `true` | When a poll closes (timer or CLOSE VOTING): the result in chat for everyone who can see the post, and on Discord (`Discord.PostPollResults`) |

Each theme has these `"R G B A"` (0–1) fields: `PanelBg`, `HeaderBg`, `ContentBg`, `ButtonPrimary`, `ButtonSecondary`, `TextTitle`, `TextNormal`, `TextMuted`. Add your own themes to the `Themes` list; the picker pages through them 8 at a time.

## News Management

`/news admin` (or `news.admin`) opens the dashboard:

- **Stat cards**: published posts (and how many are pinned), drafts, total reads (and the average per post), likes (as a share of reads) and poll votes (and how many polls are open).
- **Tabs** with counts: ALL, PUBLISHED, DRAFTS, PINNED, POLLS. **Search** looks in titles and text. The **sort** button steps through NEWEST FIRST (pinned on top), OLDEST FIRST, MOST READ and MOST LIKED.
- **Rows**: picture (when `ArchiveThumbnails` is on), title, badges (type, PINNED, DRAFT, POLL, group), date, author, `EDITED`, and in yellow when the post deletes itself or its poll closes. Then reads, likes and votes, and the buttons RESEND (PUBLISH for a draft), PIN, COPY, EDIT, DEL.
- The view (tab, search, sort) is kept while you click around and starts fresh when you type `/news admin` again.

## Editor autosave

From the first change on, what is in the editor is kept in the data file (written with the usual 15-second delay and on server save). **PUBLISH**, **SAVE DRAFT**, **SAVE CHANGES** and **CANCEL** end it. If the editor goes away any other way (disconnect, crash, server restart, plugin reload), News Management shows an **UNSAVED** bar with the title and how long ago it was changed: **CONTINUE EDITING** opens the editor as it was, **DISCARD** deletes it. If the post you were editing has been deleted meanwhile, it carries on as a new post. An autosave nobody comes back for is removed after 30 days.

## Pinned announcements

Pinned posts always sit at the top of the archive and admin list, with a gold tint, a gold **PINNED** badge and a gold frame around the popup. Pin from the admin row (**PIN / UNPIN**), from the editor (**PIN TO TOP**) or in bulk.

## Bulk admin operations

Tick the checkbox on admin rows (or **SELECT PAGE**, which takes the rows that are listed) and the footer shows **PIN ALL**, **UNPIN ALL**, **DELETE** (with confirmation) and **CLEAR**. The selection is per admin, survives paging, tabs and searches, and is dropped on disconnect.

## Drafts and copies

**SAVE DRAFT** in the editor saves a post without publishing it. Drafts appear in News Management with a `DRAFT` badge and a **PUBLISH** button; players never see them (archive, popups, `/news latest`, unread counts), and they fire no hooks and post nothing to Discord until published. Publishing (editor, **PUBLISH** button or `news.publish`) works like a new post: it moves to the top, players are notified and the auto-delete / poll timers start. Drafts are never trimmed by `MaxStoredAnnouncements` and never auto-deleted.

**COPY** opens the editor with the content and settings of any post (title, image, text, type, audience, auto-delete, countdown, poll options without votes). Saving creates a new post; the original is untouched.

## Posts for one group

**WHO CAN SEE IT** steps through `EVERYONE` and every Oxide group except `default` (which is everyone). A group-only post is shown only to members of that group (`oxide.usergroup add <player> vip`) and to admins, who see a `VIP ONLY` badge. Players outside the group don't see it in the archive, popups, toasts, unread counts or `/news latest`, and can't open, like or vote on it by id. Group-only posts stay off Discord unless `Discord.PostGroupOnlyPosts` is on.

## Auto-delete

A post with **AUTO-DELETE** set is removed that many days after it was published, exactly like a delete (`OnNewsDeleted` fires). The plugin checks every 30 seconds; an expired post is hidden immediately. News Management shows `DELETES IN 2D 4H` on the row, and `news.list` prints the time.

## Countdowns

A post with **COUNTS DOWN TO** set shows a card above its text: the countdown title on the left (default `STARTS IN`) and the time on the right, e.g. `2 DAYS  04:12:33`. The player's game counts the seconds itself; when a day runs out it asks the server for the next one, and at the end the card says `STARTED`. Archive rows show the countdown as `WIPE IN 2D 4H`.

## Player settings

`/news settings` (or **SETTINGS** in the archive) lets each player turn off:

| Setting | When off |
|---|---|
| Notification sound | No sound for new posts |
| Pop-up notifications | No toast or popup; a one-line chat message instead |
| Show new posts when I join | No popup when waking up (the unread reminder still shows) |

Choices are saved per player in the data file (`PlayerSettings`).

## Archive filters and search

Under the archive header: **ALL**, one chip per type and **POLLS**, then a search box (press Enter). The filter and search combine, the page count follows them, and prev / next in a post opened from the archive stays inside the filtered list. `/news` and **VIEW ARCHIVE** open the full archive again.

## Rounded corners

Rust's UI has no rounded rectangles, so at server start the plugin draws small anti-aliased quarter-circle images in code and stores them in the server's file store, the same place ImageLibrary keeps its pictures. ImageLibrary isn't required. Each rounded panel, card or button is built from three straight pieces plus four corner pieces, all in solid colours: a see-through colour is first mixed with the panel behind it, because the game draws see-through corner images differently from see-through panels (they would show as light squares). Shadows sit over the game view, so they are built from thin stepped strips instead. Picture corners are rounded by covering them with the background colour. If the images can't be stored, or `RoundedCorners` is `false`, everything is drawn with square corners. The first time a player opens the menu, the corner images download in a fraction of a second.

## Animations

Rust CUI can fade an element's graphic in when it appears (`FadeIn`) and out when it is destroyed (`FadeOut`); the client runs both. NewsBroadcaster uses them like this:

| Where | Animation |
|---|---|
| Opening any screen from nothing | Background fades in (0.25 s), then the content reveals top-to-bottom (0.15 s → 0.6 s) |
| Switching screens (archive ↔ post, admin → editor) | The background and the mouse cursor stay; the new screen replaces the old one in one step and fades in briefly (about 0.2 s) |
| Any click inside the same screen (filters, paging, prev/next, toggles, selection) | Instant redraw, nothing blinks |
| Toast | Fades in, fades out after `Notification.Duration` or when clicked |
| Like / vote | Like button pops, result bars fade in; rest of the popup stays still |

The menu's background layer, which also holds the mouse cursor, is created once when the menu opens and stays until it closes. Rust recentres the mouse whenever that layer is recreated, so keeping it means the cursor stays exactly where the player clicked.
| Auto-closing popups | Live "CLOSES IN %TIME_LEFT%S" countdown |

## Read tracking

A post counts as **read** for a player after its popup has stayed open for `ReadDelaySeconds`. That drives the archive's `NEW` badges, the unread counter, the admin list's read counts, the read reward and the `OnNewsRead` hook.

**Mark all read** (archive button or `/news read`) clears a player's `NEW` badges for every current post. It is stored as one timestamp per player, so it does not inflate the per-post read counts, pay read rewards or fire `OnNewsRead`. Posts published afterwards show as unread again.

## Polls

A poll is part of an announcement: the options appear in a block under the text in the popup. Before voting, players see the options as buttons; after voting they see each option's share and count, with their own choice ticked. Voting only redraws the poll block, so the reader keeps their scroll position. Each player has one vote per poll (index stored in `PollVotes`).

Editing a poll keeps existing votes: options keep their votes when you clear an empty slot in between, and votes for an option you delete are dropped. Discord posts list the poll options in an embed field.

With **POLL CLOSES** set, the poll closes on its own after that time; the popup shows `CLOSES IN 5H 12M`. When a poll closes (by its timer or with **CLOSE VOTING**), `OnNewsPollClosed` fires and, with `Polls.AnnounceResults`, everyone online who can see the post gets the result in chat (`Poll closed: Map size - winner: 4250 (48%, 21 votes).`) and Discord gets a results embed.

## API Hooks

Other plugins can subscribe to these hooks. Payloads use plain types, so consumers don't need NewsBroadcaster's internal classes.

| Hook | Signature | When it fires |
|---|---|---|
| `OnNewsBroadcast` | `void OnNewsBroadcast(Dictionary<string, object> ann)` | A new announcement is published (console or editor) |
| `OnNewsEdited` | `void OnNewsEdited(Dictionary<string, object> ann)` | An announcement is edited, pinned or unpinned |
| `OnNewsDeleted` | `void OnNewsDeleted(Dictionary<string, object> ann)` | An announcement is deleted (single, bulk, console) or trimmed by `MaxStoredAnnouncements` |
| `OnNewsRead` | `void OnNewsRead(BasePlayer player, Dictionary<string, object> ann)` | First time a player reads a post |
| `OnNewsLiked` | `void OnNewsLiked(BasePlayer player, Dictionary<string, object> ann, bool added)` | A player likes (`true`) or un-likes (`false`) a post |
| `OnNewsPollVote` | `void OnNewsPollVote(BasePlayer player, Dictionary<string, object> ann, int option)` | A player votes (or changes their vote) in a poll; `option` is the 0-based index |
| `OnNewsPollClosed` | `void OnNewsPollClosed(Dictionary<string, object> ann)` | A poll closes: its timer ran out, or an admin closed voting in the editor |

`OnNewsBroadcast` fires when a post goes live, so for a draft that is when it is published (saving a draft fires nothing). `OnNewsDeleted` also fires for auto-deleted posts.

Payload keys: `id` (string), `title`, `author`, `type` (`Info`/`Warning`/`Alert`/`Event`/`Update`), `timestamp` (UTC ticks), `date` (`yyyy-MM-dd HH:mm`), `text`, `imageUrl`, `likes` (int), `pinned` (bool) — as in the earlier builds — plus `pollOptions` (string[], empty when there is no poll), `pollVotes` (int, total votes), `group` (string, empty = everyone), `expiresAt`, `pollEndsAt` and `countdownTo` (UTC ticks, 0 = not set).

```csharp
void OnNewsBroadcast(Dictionary<string, object> ann)
{
    Puts($"[News] {ann["author"]} posted '{ann["title"]}' ({ann["type"]})");
}

void OnNewsLiked(BasePlayer player, Dictionary<string, object> ann, bool added)
{
    Puts($"{player.displayName} {(added ? "liked" : "un-liked")} {ann["title"]}");
}
```

## API methods

Other plugins can also post and read news. Call them on the plugin reference; everything uses plain types.

| Method | Returns | What it does |
|---|---|---|
| `API_PostNews(string title, string text, string type = "Info", string imageUrl = "", string author = "")` | `string` id, or `null` | Publishes a post: players are notified, Discord gets it, `OnNewsBroadcast` fires |
| `API_CreateNews(Dictionary<string, object> options)` | `string` id, or `null` | The same with every option (see below) |
| `API_DeleteNews(string id)` | `bool` | Deletes a post (`OnNewsDeleted` fires) |
| `API_GetNews(string id)` | `Dictionary<string, object>` or `null` | One post, with the same keys as the hook payload |
| `API_GetNewsList()` | `List<Dictionary<string, object>>` | Every published post, newest first |
| `API_GetUnreadCount(BasePlayer player)` | `int` | Unread posts this player can see |
| `API_ShowNews(BasePlayer player, string id)` | `bool` | Opens a post for a player; `false` when they may not see it |

`API_CreateNews` options (only `title` is required): `text`, `type`, `imageUrl`, `author` (default: the server name), `pinned`, `draft` (save without publishing), `notify` (default `true`), `discord` (default `true`), `group` (an existing Oxide group; an unknown one is refused), `expireDays` (0-365), `pollOptions` (2-4 strings), `pollHours` (0-720), `countdownTo` (UTC ticks or a `DateTime`), `countdownLabel`.

```csharp
[PluginReference] private Plugin NewsBroadcaster;

void AnnounceEvent()
{
    NewsBroadcaster?.Call("API_PostNews", "Airdrop event", "Starts in 10 minutes at the Launch Site!", "Event");
}

void AskPlayers()
{
    var id = NewsBroadcaster?.Call<string>("API_CreateNews", new Dictionary<string, object>
    {
        ["title"] = "Next event?",
        ["text"] = "Vote for Saturday's event.",
        ["type"] = "Event",
        ["author"] = "EventManager",
        ["pollOptions"] = new List<string> { "Raid base", "Boat race", "Arena" },
        ["pollHours"] = 24
    });
}
```

## Data file (`oxide/data/NewsBroadcaster_Data.json`)

Stores announcements, each player's last-seen marker, each player's "mark all read" marker (`ReadAllUpTo`) each player's `/news settings` (`PlayerSettings`: `Sound`, `Popups`, `JoinPopup`) and each admin's unsaved editor (`EditorAutosaves`). Data files from the earlier builds load unchanged.

| Field | Type | Description |
|---|---|---|
| `Id` | string | Stable id |
| `Title`, `ImageUrl`, `Text` | string | Content (`Text` uses `\n` line breaks) |
| `Date` | string | Post date shown in the UI |
| `EditedDate` | string | Last edit (empty if never edited) |
| `Author` | string | Poster |
| `Type` | enum | `Info / Warning / Alert / Event / Update` |
| `Timestamp` | long | UTC ticks — ordering and last-seen |
| `Pinned` | bool | Keeps the post on top |
| `LikedPlayers`, `ReadByPlayers` | Steam IDs | Likes and reads |
| `ReadRewardedPlayers`, `LikeRewardedPlayers` | Steam IDs | Players already paid each reward |
| `PollOptions` | list of strings | Poll options (empty = no poll) |
| `PollVotes` | Steam ID → option index | One vote per player |
| `PollClosed` | bool | Voting closed |
| `Draft` | bool | Saved but not published |
| `Group` | string | Oxide group that can see it (empty = everyone) |
| `ExpireDays`, `ExpiresAt` | int, long | Auto-delete after N days, and when (UTC ticks, 0 = never) |
| `PollHours`, `PollEndsAt` | int, long | Poll closes after N hours, and when (UTC ticks, 0 = manually) |
| `CountdownTo`, `CountdownLabel` | long, string | Countdown end (UTC ticks, 0 = none) and its title |

## Localization

All player-facing text is in Oxide's lang system (`oxide/lang/<lang>/NewsBroadcaster.json`). New keys are added to your existing lang file automatically. Keys whose meaning changed since the earlier builds were renamed so the new text shows up (`TypeLabel`, `NoPostsYet`, `PublishedNoNotify`, `ActiveBadge`); the old keys can be deleted from your lang file. The editor now uses `BodyHintShort`, and `/news help` adds `ChatHelpSettings`. `BodyHint`, `ReadMore`, `Close` and `SettingsColumn` are no longer used and can be deleted too. The "Posted by" footer and the "truncated" note of the Discord embed are lang keys as well (`DiscordPostedBy`, `DiscordTruncated`).

## Known limitations

- The popup body's scroll height is estimated from a characters-per-line guess. On very narrow (4:3) screens the last line of a very long post may sit close to the bottom edge.
- Publishing at a set time (scheduled posts) is not part of this version; save a draft and publish it when it's time.
- Polls are single-choice.
- A countdown's day count is drawn when the popup opens and redrawn when a day runs out; the seconds are counted by the player's game.
