# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

NewsBroadcaster is a single-file **Oxide/uMod plugin for the game Rust** (`NewsBroadcaster.cs`). It lets server admins post rich in-game news announcements (title, image, body, type badge) via a CUI, with player notifications, an archive viewer with unread tracking, polls, likes, rewards, Discord webhooks, and themes. Author is "DEDA"; the plugin is distributed on Codefling.

The released version is **1.0.0** (the first release, sold on RogueDepot). It is built on the author's own earlier design (the build that was numbered 1.2.0, the author's "known good" version); the 1.3–1.7 redesigns in git history were dropped. Keep that look and layout unless asked otherwise. Commit messages in the history that say 2.x are from before the renumbering; the docs call everything before 1.0.0 "the earlier builds". **1.0.0 does not read their files:** the author had every migration, old-format fallback and backfill removed before the release (config and data), and the docs tell people to remove the old config and data file. Don't add them back.

Repo contents:

## Building / running / testing

The plugin is compiled at runtime by Oxide on a Rust dedicated server:
- Drop `NewsBroadcaster.cs` into `oxide/plugins/`; Oxide hot-reloads it and prints compile errors to the console.
- Reload manually with `oxide.reload NewsBroadcaster`.
- Grant permissions: `oxide.grant user <SteamID> newsbroadcaster.admin` / `newsbroadcaster.view`.

**Before committing a change, run `tools/test-harness/run.sh`** (needs `dotnet-sdk-8.0`). It:
1. compiles the plugin as C# 6 and C# 7 against the .NET Framework 4.8 API, with stand-ins for Oxide/Rust/Unity/CUI (`Stubs/`, signatures mirror the real APIs; `BasePlayer.userID` is an `EncryptedValue<ulong>` like current Rust),
2. runs the functional suite (`Harness/Tests.cs`, ~485 checks). A simulated client tracks each player's live CUI tree and flags unknown parents or duplicate element names. The suite also holds the line on what the author's pre-release review asked for: element counts per screen, no LINQ in the plugin, every pooled list given back (`Facepunch.Pool.Outstanding`), no timer while nothing is scheduled. Two stress sections call every console command with junk arguments as console / stranger / player / admin, and walk every screen under bad config values; a new command or config option is covered by them automatically, a new screen should be added to the tour in "Config values nobody should set",
3. with `./run.sh previews`, renders every screen to PNG (`render/`, needs Node + Playwright + `fonts-roboto-unhinted`). Copy them to `previews/` when the UI changes.

`./run.sh bench` prints what the plugin itself costs (microseconds and KB of garbage to build and serialise each screen, to save each data file, `Activity.json` with 300 and 3000 readers a post, and to broadcast to 100 players). Run it before and after anything that touches drawing or saving. The numbers are .NET 8 on this machine, so compare them with each other, not with a server.

When adding a feature, add a test in `Tests.cs`. If the plugin uses a new Oxide/Rust API, add it to the stubs with the **real** signature, so a wrong call fails here as it would on a server. The stubs are not the game; a server reload is still the final check.

The harness copies what was read in the real sources (Oxide.Rust `RustCui.cs`, Facepunch `CommunityEntity.UI.cs`), because these are the things that only show in game:
- Oxide leaves out nulls and default values, and replaces the two characters `\n` in the JSON with a line break. The simulated client warns when a text had a real backslash followed by `n`.
- The game's JSON reader does not unescape, and takes a quote after a backslash for an escaped one: **a text value that ends with a backslash breaks the whole `AddUI` call**. The simulated client drops such a call and warns.
- The game's default for a missing `offsetmax` is `"1 1"`, not `"0 0"`: an element given only anchors is one unit taller and wider than its anchor box. The renderer (`render/cui.js`) does the same.
- A picture given by `url` is downloaded again every time its element is created, and nothing caches it. A `png` id is fetched once.
- Unity cannot draw more than about 16,000 characters in one text (65,000 vertices), hence `MaxContentChars` = 12000.

## Code architecture

Everything lives in `public class NewsBroadcaster : RustPlugin` inside `namespace Oxide.Plugins`, organized into `#region` blocks:

- **Fields & Constants** — layer names (`LayerName`, `NotificationLayer`, `ConfirmLayer`, `PopupPanel`, `LikeButtonName`), permissions, regexes, layout constants, and the per-player state dictionaries keyed by `ulong` SteamID: `autoCloseTimers`, `notificationTimers`, `playersWithUiOpen`, `editors` (`EditorSession` = draft + editing id + notify/discord toggles), `readRewardTimers`, `adminSelections`, `likeCooldowns`, `voteCooldowns`, `openPopups` (the id of the post in the open popup; ask `IsPopupOpen`), `currentScreens`, `toastNames`, `archivePages`, `remindedPlayers`, `archiveFilters` (archive chips + search), `adminViews` (News Management tab, search, sort and page), `redrawCooldowns` / `redrawTimers` (see the redraw cooldown below). `scheduleTimer` is a one-shot timer for the next auto-delete or poll closing (`ScheduleNextCheck`); `displayOrder` is the cached pinned-first list.
- **Data Structures** — one class per data file: `NewsData` (the announcements), `PlayerData` (`LastSeenNews` + `ReadAllUpTo` mark-all-read markers + `PlayerSettings` from `/news settings`), `ActivityData` / `PostActivity` (reads, likes, votes and paid rewards per post) and `AutosaveData` (`EditorAutosaves`, the unsaved editor session of each admin); `Announcement` (incl. `PollOptions`/`PollVotes`/`PollClosed`, `Draft`, `Group`, `ExpireDays`/`ExpiresAt`, `PollHours`/`PollEndsAt`, `CountdownTo`/`CountdownLabel`; times are UTC ticks, 0 = off), `EditorSession` (`IsDraft`, `Publishes`, `ExpireChanged`/`PollTimerChanged`, `CountdownInput`, `SavedAt`; it is also what gets autosaved, so new fields must survive JSON), `ArchiveFilter`, `AdminView`, `PopupOrigin` (`Broadcast`, `Direct`, `Archive`, `Preview`; a parameter of `ShowPopup`, not stored), and the config tree (`ConfigData` → `GeneralSettings`, `NotificationSettings`, `DiscordSettings`, `RewardSettings`/`RewardBundle`/`RewardItem`, `UIColors` themes).
- **Localization** — every player-facing string, through `Msg(key, player, args)`. If a key's meaning changes, rename the key: Oxide keeps old values in existing lang files.
- **Helpers** — text normalization (`NormalizeBodyText`, `/n` handling, optional link stripping), `F()`/`Anchor()` invariant float formatting for CUI anchors (never interpolate raw floats into anchors), title auto-sizing (`PickTitleFontSize`), lookup/permission helpers (`CanView`, `CanAdmin`, `IsAdminArg`/`RequireAdmin` for console commands, `AdminPlayer` for UI commands; the caller is always `arg.Player()`), `TryParseType` (use it instead of `Enum.TryParse`, which also accepts numbers), `SplitCommandLine` (quoted `news.show`/`news.poll` values), `IsPollOpen`, `PlaySound` (sent only to the target player via `EffectNetwork`).
- **Configuration** — the basic Oxide shape and nothing else: `LoadConfig` is `Config.ReadObject<ConfigData>()` followed by `SaveConfig()` (which writes options the file does not have yet); a file that can't be read is left alone and the defaults are used, with a console error. No migrations, no validation, no clamps, no empty `catch`: values are used as written, so code that divides by or indexes with a config value must not crash on a silly one. A file that could not be read sets `configUnreadable`, and `SaveConfig` then writes nothing (the theme picker calls it). `ConfigData.Themes` starts empty on purpose (Json.NET would merge deleted default themes back in); `LoadDefaultConfig` adds the six themes.
- **Data Management** — lifecycle hooks (`Init`, `OnServerInitialized`, `OnPluginLoaded`, `OnServerSave`, `OnPlayerSleepEnded`, `Unload`, `OnPlayerDisconnected`). **Four data files** in `oxide/data/NewsBroadcaster/`, one per kind of data, each written only when it changed (`[Flags] enum DataParts`, `dirtyParts`): `News.json` (`NewsData`: the posts, without any player data), `Activity.json` (`ActivityData`: per post id a `PostActivity` with the five player sets; built from the posts by `BuildActivity` at save time, posts with none are left out, entries are attached to their post by id on load), `Players.json` (`PlayerData`: `LastSeenNews`, `ReadAllUpTo`, `PlayerSettings`) and `Autosaves.json` (`AutosaveData`). The five sets on `Announcement` are `[JsonIgnore]`, so they never land in `News.json` or in an autosave. `NewsBroadcaster_Data.json` (the one file of the earlier builds) is neither read nor written. **Two save paths:** `SaveAnnouncements()` writes immediately (admin actions only: `News.json` plus whatever else is pending); `MarkDirty(DataParts.X)` debounces everything players cause: likes, votes, reads and paid rewards (`Activity`), last-seen, mark-all-read and settings (`Players`), editor autosaves (`Autosaves`) (`SaveDebounceSeconds` = 15 s after the first change, and flushed by `SaveData` on server save and unload). An admin action that changes activity marks it first (`RemoveAnnouncement` and the trim when the post had any, `SaveEditor` when a poll with votes is edited). Never call `SaveAnnouncements()` from a path a player triggers. The 15 s timer is the author's choice: saving only with the server save was tried and turned down, so keep the timer. What it costs is in `./run.sh bench` (`Activity.json` holds every reader of every post: ~4 MB and ~15 ms a write with 3000 readers a post; `News.json` and `Players.json` are well under 1 ms). `SaveAnnouncements` also trims (`TrimToMaxStored`: oldest published, unpinned posts first; pinned posts, drafts and the newest post are never dropped, with one console warning when pinned posts and drafts use up the limit), marks the display order dirty and calls `ScheduleNextCheck`. A data file that can't be read (`ReadDataFile` catches it) is added to `unreadableParts` and never written in that session (one console error naming it, and a chat line for an admin who opens News Management), so a typo or a half-written file is never replaced by an empty one; if it is `News.json`, nothing at all is written, since the other files belong to its posts. The four Steam-ID sets in `Activity.json` are written on one line each by `IdSetConverter` (write only: the JSON is the same, a file with one id per line still loads). `LoadAnnouncements` reads the files as they are (no old formats, no backfills, no re-sorting) and only drops per-player markers older than the oldest post (`PruneStaleMarkers`) and autosaves older than 30 days (`PruneOldAutosaves`).
  **The list is newest-first by construction** (every post is inserted at index 0, a published draft moves there), not by sorting: `NewestFor`, the trim and `GetDisplayOrder()` (pinned posts first, cached in `displayOrder`, rebuilt when `displayOrderDirty`) rely on it. Code or a test that changes `Timestamp` or `Pinned` behind the plugin's back has to keep the order and set the flag (`H.KeepNewestFirst()` in the harness).
  **Scheduling:** there is no repeating timer. `CheckScheduled` (run at startup and by the timer) deletes expired posts, closes polls whose time is up and calls `ScheduleNextCheck`, which sets one `timer.Once` for the earliest `ExpiresAt` / `PollEndsAt` (`HasExpiry` / `HasPollTimer` decide what counts, for the check and the timer alike), at most `MaxScheduleSeconds` ahead, and no timer at all when nothing is scheduled. It is called from `SaveAnnouncements`, so every admin change re-arms it; a test that edits those times by reflection calls it itself.
  **No LINQ, pooled lists:** `System.Linq` is not imported (a test fails if it comes back). Loop instead; a list needed for one call comes from `Pool.Get<List<T>>()` and goes back with `Pool.FreeUnmanaged(ref list)` (the current Facepunch API; `GetList` / `FreeList` are gone). Iterate `BasePlayer.activePlayerList` directly.
- **Visibility** — `CanSee(player, ann)` is the one rule for what a player may see: not a draft, not expired, and for everyone or one of the player's Oxide groups (admins see all groups). A permission check is a linear scan in Oxide, so loops use the overload with `ref int admin` (the admin check is made once, and only when a post has a group), and `OnPlayerSleepEnded` (called on every respawn) returns before any lookup when there is nothing new. Every player-facing path uses it (the archive and the popup's prev / next walk `GetDisplayOrder()` and keep what `CanSee` and `MatchesFilter` allow, `NewestFor` instead of `announcements[0]`, `CountUnread(player)`, `NotifyPlayers`, `news.view`/`like`/`vote`, popup navigation). The admin list shows everything.
- **Publishing** — `CreateAnnouncement` (console) and the editor go through `AddAnnouncement(ann, draft)`; `PublishDraft` turns a draft live; `ApplyPublishTimes` stamps the time and starts auto-delete / poll timers. `OnNewsBroadcast` only fires when a post goes live. `NotifyPlayers` (toast or popup per player who can see it, a chat line when the player turned pop-ups off; marks the post as seen). The toast is built and serialised once per language per broadcast (`BuildToast`, cached in a local dictionary keyed by `lang.GetLanguage`) and the same JSON goes to every player, so nothing in it may depend on the player. Every delete goes through `RemoveAnnouncement` (fires `OnNewsDeleted`; the caller saves). `CheckScheduled` deletes expired posts and closes timed polls (see Scheduling above); `AnnouncePollResults` (also for CLOSE VOTING) fires `OnNewsPollClosed`, chats the result and posts it to Discord.
- **Commands** — console/RCON (`news.show`, `news.poll`, `news.list`, `news.publish`, `news.delete`, `news.resend`, `news.trigger`, `news.admin`), the `/news` chat command (`latest`, `read`, `settings`, `admin`, `help`), and all UI button commands (`news.view`, `news.like`, `news.vote`, `news.filter`/`news.search`, `news.settings.*`, `news.countdown`, `news.admin.*` incl. `copy`/`publish`, `filter`/`search`/`sort` and `resume`/`discard` for the autosave, `news.editor.*` incl. `savedraft` and the `audience`/`expire`/`polltimer` cycles). Admin UI commands get the player through `AdminPlayer(arg)`.
  **Redraw cooldown:** `news.page`, `news.filter`, `news.search`, `news.search.clear` and `news.admin.page` / `filter` / `search` / `sort` store what was picked (`archivePages`, `archiveFilters`, `AdminView`) and call `RedrawThrottled(player, screen)`: at most one redraw per `RedrawCooldownSeconds` per player. A click inside the cooldown is not dropped (an input field sends its search together with the click that ended the typing); one timer draws the latest state when the cooldown ends. `OpenScreen` and `DestroyUI` cancel a waiting redraw, and a dialog draws it first (`FlushRedraw`) so it can't be closed by it. Like and vote have their own (dropping) cooldowns.
- **Notification UI / UI Generation / Admin UI / Theme UI** — CUI construction with manual anchor math. A screen is built in a `Ui` (nested class, a `CuiElementContainer`): its `Add(CuiLabel…)` and `Leaf(Piece…)` add elements **without a name**, its `Add(CuiPanel…)` / `Add(CuiButton…)` give a short `nb_<hex>` name from one counter (Oxide's own `Add` would make a 32-character GUID for every element), and `Surfaces` holds the opaque colour of each surface for `ColorUnder`. Send with `SendUi(player, container)`, never `CuiHelper.AddUi` directly: `UiJson` first makes every text safe for the game (a space after a trailing backslash, typographic instead of straight double quotes). `SwapUi(player, container, name)` sets `destroyUi` on the named root so an in-place update is one message; the root must contain everything it draws (a named `AddBox` with a rim is therefore the rim-coloured box with the fill inside it, while an unnamed one keeps its rim as a sibling whose offsets allow for the client's `offsetmax` default). No quotes inside button commands. Pictures go through `AddPicture` (offsets written out); list thumbnails only use what `GetImage` finds in ImageLibrary, the popup falls back to the link. `F()`, `Blend()`, `Opaque()` and `RgbaToHex()` remember their results; type names and labels come from `TypeNames` / `TypeLabels` (keep them in the order of the enum). Each screen is rebuilt and pushed whole, except the like button (`AddLikeButton`), the poll block (`AddPollBlock`, laid out by `PollLayout`) and the countdown card (`AddCountdownBlock`, redrawn by `news.countdown` when the client's timer runs out), which are swapped in place so the reader's scroll position is kept. News Management (`ShowAdminList`) is a dashboard laid out in units through the small `Grid` struct (units from the top-left of the panel or a row → anchors): header, `AddAdminStats` (five cards), `AddAdminToolbar` (tabs with counts, sort cycle, `AddSearchField` shared with the archive), the optional unsaved bar, `AddAdminRow` per post (rows share the space left, so they get thinner with more `AnnouncementsPerPage` or with the bar; `compact` under 46 units) and `AddAdminFooter` (select page, bulk actions, pager). `FillAdminOrder(userId, list)` fills a pooled list as that admin filtered and sorted it; `news.admin.selectpage` uses it too. Only PUBLISH on a draft row is a filled button. The editor is two columns (content left, settings right); its counters and hints (`AddEditorHints`) are named labels swapped by `RefreshEditorHint` after typing. Shared look ("premium" style): `AddBackdrop` (dim + blur material), `AddPanelShadow` (two stepped translucent layers, 14 elements, added before the panel), `AddSurface` (rounded holder for panels, cards and the main button; optional `rim` drawn just outside an opaque fill; content goes on top), `AddBox` (the flat one-element version for everything small, same colour blending, rim as a slightly larger box behind), `AddRoundedFill`, `AddPill` (box + label), `AddPrimaryButton` (rounded) / `AddGhostButton` (one `CuiButton` with its text: 2 elements), `AddCornerMasks` (rounds picture corners by covering them with the background colour; the popup picture only), `AddTopSheen`, `AddHairline`, `AddAccentBar`. Filled buttons are reserved for the main action. Use `Blend()`/`Opaque()` to get opaque colours wherever a rim or picture mask needs to match the background exactly. `ParseColor` keeps what it parsed (`parsedColors`, the arrays are shared: read them, don't change them), since a screen asks for the same few colours hundreds of times; `AddBox` registers its colour like `AddRoundedFill` does, so `ColorUnder` rarely has to search the container.
  **Rounded corners:** `GenerateCornerTextures()` (OnServerInitialized) draws 8 quarter-circle PNGs in code (`BuildCornerPng` + a minimal `EncodePng`, no System.IO) and stores them with `FileStorage.server.StoreByCrc(CommunityEntity.ServerInstance.net.ID, FileStorage.Type.png, bytes)` (the API since the November 2026 Rust update; the old `Store(bytes, type, id)` no longer compiles). Each rounded rect is 4 corner RawImages, then 3 bands on top (7 elements plus the holder); the side bands reach `SeamOverlap` into the corners to hide a texture-wrap seam seen in game. If storing fails or `RoundedCorners` is off, `Rounded` is false and `AddSurface` is `AddBox`.
  **Element budget (the author's review: "the rounded corners make the ui really heavy").** Every element is sent to the player on every redraw, so only panels, cards (archive / admin rows, stat cards, poll and countdown cards, theme cards), the filled main button and the popup picture are rounded. Buttons, tags, badges, chips, input and search fields, check boxes, poll rows and bars, thumbnails and accent bars are flat (`AddBox` / a plain `Piece`). An archive page went from ~370 elements to ~160 (~100 with `RoundedCorners` off), the popup from ~150 to ~60, the toast from 61 to 36; tests in the "Rounded corners" section fail when a screen grows past its budget. Before rounding anything new, count what it adds per row.
  **Corner pieces must be opaque.** In game a translucent RawImage blends in linear colour space (much brighter than a translucent Image panel of the same colour), and low-alpha Image panels come out fainter than in the browser previews; only opaque colours look identical everywhere. So `AddRoundedFill`/`AddSurface` pre-blend translucent colours onto the opaque surface below, found by `ColorUnder()` (surfaces registered by `AddRoundedFill`/`SetSurface`, then the element's parents in the container). Anything rounded that is redrawn on its own (poll block, countdown card) calls `SetSurface` for the popup panel first. Shapes over the game view (shadows) have no known colour below and use `AddSteppedFill` (Image slices only, drawn straight onto the parent over a given anchor box, no holder). Hairlines and the top sheen are pre-blended too. Picture masks have transparent top/bottom texture rows (pieces one texel taller). The simulated client warns about translucent corner pieces.
  **Screens and the cursor:** every full-screen view starts with `OpenScreen(player, UiScreen.X, out fresh)` then `BeginScreen(container, fresh, backdrop)`, and parents its content to `ScreenName`. The root `LayerName` (backdrop + `CursorEnabled`) is only created when the menu opens and is never destroyed to redraw: Rust recentres the mouse whenever the cursor element is recreated, and a destroy-then-add blinks. `ScreenName` is added with `destroyUi = ScreenName`, so the client swaps the old view for the new one in one step. Dialogs on `ConfirmLayer` do the same (`ShowConfirmDialog`; the settings dialog swaps only `ConfirmLayer.Body`). The simulated client counts `CursorGrabs`; tests check it stays at 1 while clicking around.
  **Animations:** `OpenScreen` returns 1 when the menu opens, `SwitchFade` when moving to another view and 0 for a redraw of the same view (instant); views end with `ApplyFadeRamp(container, contentStart, first * anim, last * anim)`, which fills in `FadeIn` for every element added after `contentStart` (later elements fade slower → top-to-bottom reveal). Don't hard-code `FadeIn` unless the fade is intentional and only on an in-place swap (like pop, poll bars after a vote); the background only fades when `fresh`. Toasts use a unique name per toast (`toastNames`) so `FadeOut` can cross-fade them. Full-screen layers deliberately have no `FadeOut` (a fading layer would share names with the next screen). `tools/test-harness/run.sh video` renders an MP4/GIF of the animations. The editor is not rebuilt on text input, so fields don't lose focus.
- **Editor autosave** — every editor command that changes something calls `AutosaveEditor` (the session object itself is put in `autosaveData.EditorAutosaves`, saved through `MarkDirty`). Save, publish and cancel end it through `CloseEditor`; a disconnect only drops the in-memory session, so News Management shows the UNSAVED bar (`AddUnsavedBanner`, `news.admin.resume` / `news.admin.discard`). `PruneOldAutosaves` drops the ones older than 30 days on load.
- **API** (`#region API`) — private `API_*` methods other plugins call (`API_PostNews`, `API_CreateNews` with an options dictionary, `API_DeleteNews`, `API_GetNews`, `API_GetNewsList`, `API_GetUnreadCount`, `API_ShowNews`). Documented in `PLUGIN_DOCS.md`: don't rename them or change their parameters.
- **Rewards** — read/like payouts (items through `player.GiveItem`, which drops them when the inventory is full; ServerRewards points with a plain `ulong` id; Economics currency), at most once per player per announcement. `CanGrantRewardBundle` checks shortnames and plugins before anything is paid, so `GiveRewards` does not re-check. The "paid" lists are saved through `MarkDirty`. A bundle that can't be paid (missing plugin, unknown shortname) is reported once per problem (`warnedRewardProblems`), not once per player.
- **Discord Webhooks** — embed per post; only the configured `RoleMention` may ping.

### Cross-cutting things to know

- **Optional integrations** are `[PluginReference] private Plugin ImageLibrary, Notify, ServerRewards, Economics;` — always null-check and `IsLoaded`-check; the plugin must work without them.
- **API hooks** fired via `Interface.CallHook`: `OnNewsBroadcast`, `OnNewsEdited`, `OnNewsDeleted`, `OnNewsRead`, `OnNewsLiked`, `OnNewsPollVote`, `OnNewsPollClosed`, with payloads from `BuildHookData(ann)`. These are a documented public contract — don't rename or drop keys.
- **Per-player cleanup**: every SteamID-keyed collection must be cleared in `OnPlayerDisconnected` and `Unload` (the test suite checks this by name; add new collections to that test).
- **`FileStorage` changed in the November 2026 Rust update**: use `StoreByCrc(entityId, type, data)`; `Store(...)` is gone. The stub mirrors this.
- **CUI countdowns** use the real Oxide `CuiCountdownComponent` (float `StartTime`/`EndTime`/`Step`/`Interval`, `TimerFormat`, `Command`); the client fills `%TIME_LEFT%`. Days are drawn as text because the day format of `DaysHoursMinutesSeconds` isn't documented.
- **`ConsoleSystem.Arg.FullString` is a `StringView` on current Rust**, not a string: always write `arg.FullString.ToString()` (never `arg.FullString ?? ...`). **`arg.Args` is a `Facepunch.StringView[]`**, not a `string[]`: `string.Join(" ", arg.Args, ...)` compiles but prints `Facepunch.StringView[]` (that broke the theme picker in game). Read arguments with `arg.GetString(i)`, join them with `JoinArgs(arg, from, to)`, count them with `ArgCount(arg)`. The stub mirrors both.
- **Oxide sandbox / compatibility**: stay within C# 6/7 features and .NET Framework 4.x APIs; no `System.IO`, `System.Net`, `System.Reflection` or threading. Only `Oxide.*`, `UnityEngine`, `Newtonsoft.Json` and the game assemblies are available.
- **Version** lives in `[Info("NewsBroadcaster", "DEDA", "x.y.z")]`; bump it and the version in `PLUGIN_DOCS.md` together.

## Conventions

- No comments in `NewsBroadcaster.cs` (see above); `#region` blocks stay.
- Match the existing idioms: regions, manual CUI anchor math via `Anchor()`/`F()`, `Msg()` for all user-facing text, defensive null checks around plugin references.
- CUI colours are RGBA strings like `"0.10 0.08 0.07 0.97"`, consistent with Rust's CUI.
- CUI sizing assumes the 1280x720 reference canvas (font sizes and offsets are in those units; the popup is 832x468 units).
