# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

NewsBroadcaster is a single-file **Oxide/uMod plugin for the game Rust** (`NewsBroadcaster.cs`). It lets server admins post rich in-game news announcements (title, image, body, type badge) via a CUI, with player notifications, an archive viewer with unread tracking, polls, likes, rewards, Discord webhooks, and themes. Author is "DEDA"; the plugin is distributed on Codefling.

The released version is **1.0.0** (the first release, sold on RogueDepot). It is built on the author's own earlier design (the build that was numbered 1.2.0, the author's "known good" version); the 1.3–1.7 redesigns in git history were dropped. Keep that look and layout unless asked otherwise. Commit messages in the history that say 2.x are from before the renumbering; the docs call everything before 1.0.0 "the earlier builds", and their config and data still load.

Repo contents:
- `NewsBroadcaster.cs` — the entire plugin (~5720 lines, one class).
- `PLUGIN_DOCS.md` — admin reference (commands, permissions, config, API hooks, what's new).
- `CHANGELOG.md` — release notes (1.0.0 = everything, including what changed since the earlier builds).
- `ROGUEDEPOT_LISTING.md` — what goes in each field of RogueDepot's listing form (name, tagline, tags, which files and screenshots in which order, notes for their review); `ROGUEDEPOT_DESCRIPTION.md` is the description itself, pasted whole into the form (Markdown, no escaped pipes in tables). Keep both in step with the plugin, like the Codefling text.
- `CODEFLING_DESCRIPTION.md` — marketing copy for the store listing.
- `previews/` — rendered screenshots of every screen (from the test harness).
- `site/` — the product page as a static website (`index.html`, `favicon.svg`, `shots/` = WebP copies of `previews/`, `media/animations.mp4`). No build step: it is uploaded as-is to Cloudflare Pages (drag and drop the folder or a zip of its contents, or `npx wrangler pages deploy site`). Keep its feature list, requirements and screenshots in step with the plugin.

Text is outlined, so the SVGs need no font. Change `logo.svg`, then run the script.
- `tools/test-harness/` — compile checks, functional tests and the screenshot renderer (see below).

## Building / running / testing

The plugin is compiled at runtime by Oxide on a Rust dedicated server:
- Drop `NewsBroadcaster.cs` into `oxide/plugins/`; Oxide hot-reloads it and prints compile errors to the console.
- Reload manually with `oxide.reload NewsBroadcaster`.
- Grant permissions: `oxide.grant user <SteamID> newsbroadcaster.admin` / `newsbroadcaster.view`.

**Before committing a change, run `tools/test-harness/run.sh`** (needs `dotnet-sdk-8.0`). It:
1. compiles the plugin as C# 6 and C# 7 against the .NET Framework 4.8 API, with stand-ins for Oxide/Rust/Unity/CUI (`Stubs/`, signatures mirror the real APIs; `BasePlayer.userID` is an `EncryptedValue<ulong>` like current Rust),
2. runs the functional suite (`Harness/Tests.cs`, ~340 checks). A simulated client tracks each player's live CUI tree and flags unknown parents or duplicate element names,
3. with `./run.sh previews`, renders every screen to PNG (`render/`, needs Node + Playwright + `fonts-roboto-unhinted`). Copy them to `previews/` when the UI changes.

When adding a feature, add a test in `Tests.cs`. If the plugin uses a new Oxide/Rust API, add it to the stubs with the **real** signature, so a wrong call fails here as it would on a server. The stubs are not the game; a server reload is still the final check.

## Code architecture

Everything lives in `public class NewsBroadcaster : RustPlugin` inside `namespace Oxide.Plugins`, organized into `#region` blocks:

- **Fields & Constants** — layer names (`LayerName`, `NotificationLayer`, `ConfirmLayer`, `PopupPanel`, `LikeButtonName`), permissions, regexes, layout constants, and the per-player state dictionaries keyed by `ulong` SteamID: `autoCloseTimers`, `notificationTimers`, `playersWithUiOpen`, `editors` (`EditorSession` = draft + editing id + notify/discord toggles), `readRewardTimers`, `adminSelections`, `likeCooldowns`, `voteCooldowns`, `openPopups`, `currentScreens`, `toastNames` (which post a popup shows and its `PopupOrigin`), `archivePages`, `remindedPlayers`, `archiveFilters` (archive chips + search), `adminViews` (News Management tab, search and sort). `scheduleTimer` runs `CheckScheduled` every 30 s.
- **Data Structures** — `StoredData` (announcements + `LastSeenNews` + `ReadAllUpTo` mark-all-read markers + `PlayerSettings` from `/news settings` + `EditorAutosaves`, the unsaved editor session of each admin), `Announcement` (incl. `PollOptions`/`PollVotes`/`PollClosed`, `Draft`, `Group`, `ExpireDays`/`ExpiresAt`, `PollHours`/`PollEndsAt`, `CountdownTo`/`CountdownLabel`; times are UTC ticks, 0 = off), `EditorSession` (`IsDraft`, `Publishes`, `ExpireChanged`/`PollTimerChanged`, `CountdownInput`, `SavedAt`; it is also what gets autosaved, so new fields must survive JSON), `ArchiveFilter`, `AdminView`, `PopupState`/`PopupOrigin` (`Broadcast`, `Direct`, `Archive`, `Preview`), and the config tree (`ConfigData` → `GeneralSettings`, `NotificationSettings`, `DiscordSettings`, `RewardSettings`/`RewardBundle`/`RewardItem`, `UIColors` themes).
- **Localization** — every player-facing string, through `Msg(key, player, args)`. If a key's meaning changes, rename the key: Oxide keeps old values in existing lang files.
- **Helpers** — text normalization (`NormalizeBodyText`, `/n` handling, optional link stripping), `F()`/`Anchor()` invariant float formatting for CUI anchors (never interpolate raw floats into anchors), title auto-sizing (`PickTitleFontSize`), lookup/permission helpers (`CanView`, `CanAdmin`, `IsAdminArg`/`RequireAdmin` for console commands, `AdminPlayer` for UI commands; the caller is always `arg.Player()`), `TryParseType` (use it instead of `Enum.TryParse`, which also accepts numbers), `SplitCommandLine` (quoted `news.show`/`news.poll` values), `IsPollOpen`, `PlaySound` (sent only to the target player via `EffectNetwork`).
- **Configuration** — `LoadConfig` migrates older shapes through `JObject` (legacy reward arrays, missing themes), validates and clamps, and re-saves when the file is missing newer keys. Keep this migration path when changing the schema.
- **Data Management** — lifecycle hooks (`Init`, `OnServerInitialized`, `OnPluginLoaded`, `OnServerSave`, `OnPlayerSleepEnded`, `Unload`, `OnPlayerDisconnected`). **Two save paths:** `SaveAnnouncements()` writes immediately (admin actions, rewards paid); `MarkDataDirty()` debounces likes/reads/last-seen (15 s, flushed on server save and unload). `LoadAnnouncements` repairs old data, sorts newest-first and drops per-player markers older than the oldest post (`PruneStaleMarkers`).
- **Visibility** — `CanSee(player, ann)` is the one rule for what a player may see: not a draft, not expired, and for everyone or one of the player's Oxide groups (admins see all groups). Every player-facing path uses it (archive via `VisibleOrder`/`ArchiveOrder`, `NewestFor` instead of `announcements[0]`, `CountUnread(player)`, `NotifyPlayers`, `news.view`/`like`/`vote`, popup navigation). The admin list shows everything.
- **Publishing** — `CreateAnnouncement` (console) and the editor go through `AddAnnouncement(ann, draft)`; `PublishDraft` turns a draft live; `ApplyPublishTimes` stamps the time and starts auto-delete / poll timers. `OnNewsBroadcast` only fires when a post goes live. `NotifyPlayers` (toast or popup per player who can see it, a chat line when the player turned pop-ups off; marks the post as seen). Every delete goes through `RemoveAnnouncement` (fires `OnNewsDeleted`; the caller saves). `CheckScheduled` deletes expired posts and closes timed polls; `AnnouncePollResults` (also for CLOSE VOTING) fires `OnNewsPollClosed`, chats the result and posts it to Discord.
- **Commands** — console/RCON (`news.show`, `news.poll`, `news.list`, `news.publish`, `news.delete`, `news.resend`, `news.trigger`, `news.admin`), the `/news` chat command (`latest`, `read`, `settings`, `admin`, `help`), and all UI button commands (`news.view`, `news.like`, `news.vote`, `news.filter`/`news.search`, `news.settings.*`, `news.countdown`, `news.admin.*` incl. `copy`/`publish`, `filter`/`search`/`sort` and `resume`/`discard` for the autosave, `news.editor.*` incl. `savedraft` and the `audience`/`expire`/`polltimer` cycles). Admin UI commands get the player through `AdminPlayer(arg)`.
- **Notification UI / UI Generation / Admin UI / Theme UI** — CUI construction with manual anchor math. Each screen is rebuilt and pushed whole, except the like button (`AddLikeButton`), the poll block (`AddPollBlock`, laid out by `PollLayout`) and the countdown card (`AddCountdownBlock`, redrawn by `news.countdown` when the client's timer runs out), which are swapped in place so the reader's scroll position is kept. News Management (`ShowAdminList`) is a dashboard laid out in units through the small `Grid` struct (units from the top-left of the panel or a row → anchors): header, `AddAdminStats` (five cards), `AddAdminToolbar` (tabs with counts, sort cycle, `AddSearchField` shared with the archive), the optional unsaved bar, `AddAdminRow` per post (rows share the space left, so they get thinner with more `AnnouncementsPerPage` or with the bar; `compact` under 46 units) and `AddAdminFooter` (select page, bulk actions, pager). `AdminOrder(userId)` is the list as that admin filtered and sorted it; `news.admin.selectpage` uses it too. Only PUBLISH on a draft row is a filled button. The editor is two columns (content left, settings right); its counters and hints (`AddEditorHints`) are named labels swapped by `RefreshEditorHint` after typing. Shared look ("premium" style): `AddBackdrop` (dim + blur material), `AddPanelShadow` (layered rounded shadow, added before the panel), `AddSurface` (rounded card/button holder; optional `rim` drawn just outside an opaque fill; content goes on top), `AddRoundedFill`, `AddPill`, `AddPrimaryButton` / `AddGhostButton`, `AddCornerMasks` (rounds picture corners by covering them with the background colour), `AddTopSheen`, `AddHairline`, `AddAccentBar`. Filled buttons are reserved for the main action. Use `Blend()`/`Opaque()` to get opaque colours wherever a rim or picture mask needs to match the background exactly.
  **Rounded corners:** `GenerateCornerTextures()` (OnServerInitialized) draws 8 quarter-circle PNGs in code (`BuildCornerPng` + a minimal `EncodePng`, no System.IO) and stores them with `FileStorage.server.StoreByCrc(CommunityEntity.ServerInstance.net.ID, FileStorage.Type.png, bytes)` (the API since the November 2026 Rust update; the old `Store(bytes, type, id)` no longer compiles). Each rounded rect is 4 corner RawImages, then 3 bands on top (~7 elements), so keep rounded elements to things that matter; the side bands reach `SeamOverlap` into the corners to hide a texture-wrap seam seen in game. If storing fails or `RoundedCorners` is off, `Rounded` is false and every helper draws plain rectangles.
  **Corner pieces must be opaque.** In game a translucent RawImage blends in linear colour space (much brighter than a translucent Image panel of the same colour), and low-alpha Image panels come out fainter than in the browser previews; only opaque colours look identical everywhere. So `AddRoundedFill`/`AddSurface` pre-blend translucent colours onto the opaque surface below, found by `ColorUnder()` (surfaces registered by `AddRoundedFill`/`SetSurface`, then the element's parents in the container). Anything redrawn on its own (like button, poll block) calls `SetSurface` for the popup panel first. Shapes over the game view (shadows) have no known colour below and use `AddSteppedFill` (Image slices only). Hairlines and the top sheen are pre-blended too. Picture masks have transparent top/bottom texture rows (pieces one texel taller). The simulated client warns about translucent corner pieces.
  **Screens and the cursor:** every full-screen view starts with `OpenScreen(player, UiScreen.X, out fresh)` then `BeginScreen(container, fresh, backdrop)`, and parents its content to `ScreenName`. The root `LayerName` (backdrop + `CursorEnabled`) is only created when the menu opens and is never destroyed to redraw: Rust recentres the mouse whenever the cursor element is recreated, and a destroy-then-add blinks. `ScreenName` is added with `destroyUi = ScreenName`, so the client swaps the old view for the new one in one step. Dialogs on `ConfirmLayer` do the same (`ShowConfirmDialog`; the settings dialog swaps only `ConfirmLayer.Body`). The simulated client counts `CursorGrabs`; tests check it stays at 1 while clicking around.
  **Animations:** `OpenScreen` returns 1 when the menu opens, `SwitchFade` when moving to another view and 0 for a redraw of the same view (instant); views end with `ApplyFadeRamp(container, contentStart, first * anim, last * anim)`, which fills in `FadeIn` for every element added after `contentStart` (later elements fade slower → top-to-bottom reveal). Don't hard-code `FadeIn` unless the fade is intentional and only on an in-place swap (like pop, poll bars after a vote); the background only fades when `fresh`. Toasts use a unique name per toast (`toastNames`) so `FadeOut` can cross-fade them. Full-screen layers deliberately have no `FadeOut` (a fading layer would share names with the next screen). `tools/test-harness/run.sh video` renders an MP4/GIF of the animations. The editor is not rebuilt on text input, so fields don't lose focus.
- **Editor autosave** — every editor command that changes something calls `AutosaveEditor` (the session object itself is put in `storedData.EditorAutosaves`, saved through `MarkDataDirty`). Save, publish and cancel end it through `CloseEditor`; a disconnect only drops the in-memory session, so News Management shows the UNSAVED bar (`AddUnsavedBanner`, `news.admin.resume` / `news.admin.discard`). `RepairAutosaves` drops broken or 30-day-old ones on load.
- **API** (`#region API`) — private `API_*` methods other plugins call (`API_PostNews`, `API_CreateNews` with an options dictionary, `API_DeleteNews`, `API_GetNews`, `API_GetNewsList`, `API_GetUnreadCount`, `API_ShowNews`). Documented in `PLUGIN_DOCS.md`: don't rename them or change their parameters.
- **Rewards** — read/like payouts (items, ServerRewards points with a plain `ulong` id, Economics currency), at most once per player per announcement.
- **Discord Webhooks** — embed per post; only the configured `RoleMention` may ping.

### Cross-cutting things to know

- **Optional integrations** are `[PluginReference] private Plugin ImageLibrary, Notify, ServerRewards, Economics;` — always null-check and `IsLoaded`-check; the plugin must work without them.
- **API hooks** fired via `Interface.CallHook`: `OnNewsBroadcast`, `OnNewsEdited`, `OnNewsDeleted`, `OnNewsRead`, `OnNewsLiked`, `OnNewsPollVote`, `OnNewsPollClosed`, with payloads from `BuildHookData(ann)`. These are a documented public contract — don't rename or drop keys.
- **Per-player cleanup**: every SteamID-keyed collection must be cleared in `OnPlayerDisconnected` and `Unload` (the test suite checks this by name; add new collections to that test).
- **`FileStorage` changed in the November 2026 Rust update**: use `StoreByCrc(entityId, type, data)`; `Store(...)` is gone. The stub mirrors this.
- **CUI countdowns** use the real Oxide `CuiCountdownComponent` (float `StartTime`/`EndTime`/`Step`/`Interval`, `TimerFormat`, `Command`); the client fills `%TIME_LEFT%`. Days are drawn as text because the day format of `DaysHoursMinutesSeconds` isn't documented.
- **`ConsoleSystem.Arg.FullString` is a `StringView` on current Rust**, not a string: always write `arg.FullString.ToString()` (never `arg.FullString ?? ...`). The stub mirrors this.
- **Oxide sandbox / compatibility**: stay within C# 6/7 features and .NET Framework 4.x APIs; no `System.IO`, `System.Net`, `System.Reflection` or threading. Only `Oxide.*`, `UnityEngine`, `Newtonsoft.Json` and the game assemblies are available.
- **Version** lives in `[Info("NewsBroadcaster", "DEDA", "x.y.z")]`; bump it and the version in `PLUGIN_DOCS.md` together.

## Conventions

- Match the existing idioms: regions, manual CUI anchor math via `Anchor()`/`F()`, `Msg()` for all user-facing text, defensive null checks around plugin references.
- CUI colours are RGBA strings like `"0.10 0.08 0.07 0.97"`, consistent with Rust's CUI.
- CUI sizing assumes the 1280x720 reference canvas (font sizes and offsets are in those units; the popup is 832x468 units).
